## 首要关口与执行顺序

仓库整理已先提交并推送为 `a63a725`，随后继续阶段 1，保持用户指定的执行顺序。已授权的阶段 1 仅为临时无敏感健康探针，不接生产 MCP 或现有显示服务，不修改网络、权限、睡眠或信任设置，不安装第三方 App、不配置自启或永久入口。结束后清理本次拥有的临时进程与文件。

当前已验证 Quest 3 / Android 14 / API 34 / ARM64 及 cloudflared 2026.10.7 在 ADB shell 下执行，本地固定健康响应正常。提交后复测确认 Linux 发布资产在申请 Tunnel 前使用 Go DNS 解析失败；Quest 系统解析同一地址成功。本次未建立隧道，未执行外部 HTTPS 请求，阶段 1 尚未通过。临时进程、设备与开发机的隔离文件已清理，探针端口已关闭。下一项是 Android 解析适配的最小验证，再复测公网回环；不先修改设备 DNS 或安装辅助 App。详情见[验证记录](validation-baseline.md)。

**不能合并的验收项：**二进制执行、出站隧道与外部健康回环、自动启动 / 失败恢复、自研 APK 内置、长时 / 休眠 / 网络切换。ADB shell 的权限和生命周期不同于正式 App；阶段 1 通过后仍不能把后四项标为完成。

阶段 2 与 3 都是完整工作区的前置证据。遇到内置限制可以评估已经确认允许的后台辅助组件，但不能直接安装或启用它；遇到语音或共存限制先记录实际冲突。常在线服务端只在明确需求或实测限制下由用户再决定，不自行迁移 MCP 主位置。
