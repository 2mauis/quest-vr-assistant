# M0–M5 与验收

> 待 VPS 改版更新：涉及公网部署的里程碑需随 VPS 调研复核。

沿用 v1 的逐层验证、面板、唤醒声纹、Bot 闭环与完善顺序，按原生 app + VPS 路线 M 调整。周期为单人施工估计，不是交付承诺。

| 阶段 | 计划 | 产出与通过门槛 |
|---|---|---|
| M0 可行性闸门 | 第 1 周前半 | 原生面板与本地模型最小实机验证；确认云端远程 MCP、鉴权、协议版本；验证 utterance → routine webhook → MCP 回调与关联 ID；测首包延迟，不存在可用入口则阻塞语音闭环 |
| M1 VPS 与假客户端 | 第 1 周后半 | 待 VPS 改版更新：证书、Caddy、systemd；MCP render 工具经 WSS 到假客户端；断网 30 秒后 resume 无重复应用；离线、过期与撤销正确返回 |
| M2 原生面板 | 第 2–3 周 | 安装独立原生 app，中文 Markdown 显示、更新、清除，位置可调整；可见后 ack；权限撤回及摘下停止采音 |
| M3 本地唤醒与声纹 | 第 3–5 周 | 达到下列全部语音指标；失败不发 utterance，无模板、原始音频或声纹分数外传；完成删除重注册验证 |
| M4 路线 M 闭环 | 第 5–6 周 | 机主语音 → Bot → 浮空回复；Git、X 复用现有连接器；端到端首包达到下列目标，不以仅能显示视为完成 |
| M5 完善与恢复 | 后续迭代 | 流式更新、回声与打断、失焦恢复、可选模型/图表；限流、费用上限、证书续期检查及冷恢复演练；持续运行稳定性测试 |

## 统一验收指标

| 指标 | 门槛 | 方法 |
|---|---|---|
| 误唤醒 | ≤0.5 次/小时 | 至少 10 小时非唤醒声音与日常噪声，分别统计唤醒候选和双门通过 |
| 唤醒率 | 安静 ≥95%，嘈杂 ≥90% | 每条件至少 100 次，冻结阈值，记录噪声条件 |
| 本人通过率 | ≥95% | 至少 100 次独立尝试 |
| 他人通过率 | ≤1% | 至少 300 次独立尝试，多说话人及回放单列 |
| 声纹附加延迟 | ≤150ms 目标 | 端侧推理实测；补句等待另外报告 |
| 首包回复 | P50 ≤1.5s，P90 ≤2.5s | 至少 100 次完整往返，安静/嘈杂与冷/热状态分组，含失败和超时计数 |

首包定义：机主说完问题的最后一个音频样本时间，到 app 首次可见的有效回复正文；包括 VAD 尾静音、STT、上行、云端调度和推理、MCP、下行、渲染。确认提示、占位动画与心跳不算回复。仅另报服务器首字节诊断值，不替代此指标。统一用头显单调时钟关联开始与显示，避免跨机时钟误差。

streamable HTTP/SSE 不保证模型逐字流式输出。若 Bot 只调用一次完整 render，也按首次可见正文计时。参考资料中的“30 秒内出现结果”仅可用作早期连通性检查，不能替代当前 P50/P90 目标。任一目标未达到，报告实测、瓶颈和决策，不能静默降低门槛。

## 验证记录模板

每次记录：匿名测试编号、app/模型/协议版本、条件、样本量、成功/失败/超时计数、P50/P90、误通过数、阈值、问题与复测结论。日志脱敏，不保存声音、文本正文、身份或部署地址。网络中断、重复请求、乱序、队列溢出、重启、凭据过期与撤销必须各有验证证据。
