# 原生 VR app

## 候选比较

以下为离线工程判断；SDK 版本、许可与实际设备能力待施工时核实，不宣称已做性能测试。

| 候选 | 空间面板与语音接入 | 优点 | 代价与风险 | 建议 |
|---|---|---|---|---|
| Meta Spatial SDK | Kotlin 原生空间 app，Android UI 面板，原生音频与 ONNX 接入 | 面板中心的助手较轻，贴近 Android 生命周期 | 复杂三维特效与交互需更多自建；版本和失焦能力待测 | MVP 首选 |
| Unity + Meta XR SDK | 三维场景、手势、世界空间 UI，通过原生桥接接入语音 | 交互与资产工具链成熟，适合扩展丰富 HUD | 包体、启动与内存开销；音频桥接和授权需核实 | 复杂空间交互时优先替换候选 |
| Unreal | 完整三维场景与高质量材质，原生音频集成 | 视觉表现与场景工具完善 | 面板型助手投入偏重，移动渲染调优成本较高 | 仅在高视觉需求明确后评估 |
| WebXR | 浏览器三维面板与浏览器音频 | 易分享原型 | 后台录音、推理运行时、权限和生命周期限制待测 | 仅备选，不转为 APK 壳 |

推荐 Meta Spatial SDK 的理由是 MVP 核心为文字面板、语音与设备生命周期，而非大型三维场景。M0 同机验证文字清晰度、音频运行时与帧稳定性后冻结引擎；不并行建设三套实现。

## 钢铁侠风格交互

以低干扰透视空间为背景：前方主回复面板、侧方任务卡、简洁语音波形、连接与身份状态。冷色细线、半透明边框、分层卡片；高对比正文，避免闪烁、满视野动画与遮挡安全视野。机主可移动、缩放、固定、关闭或重置面板。不要强制面板随头抖动。

起始面板距离约 1–2 米，宽约 0.6–1.2 米，仅为可调初值。实机检查中文长段落、换行、滚动、字幕和透视背景下的可读性。默认最多 3 块面板；TTS 为可选，文本回复必须始终可见。

## 音频与生命周期

状态：待机 → 唤醒候选 → 声纹验证 → 监听问题 → 本地 STT → 等待回复 → 渲染/播报 → 待机。声纹失败不得上传文本或开启云端会话。录音有持续可见指示，可一键静音。

一个采集管线共享给 VAD、唤醒、声纹和 STT，避免多录音器争用。播放回复时做回声抑制；未证明抗回声能力前暂停唤醒，打断能力在 M5 单独验收。摘下、失焦、权限撤回与系统暂停时停止采音、清空短期缓存；恢复前检查权限与本地会话状态。不得承诺系统不允许的后台常驻。

## 渲染边界

支持中文 Markdown 的受限子集；禁用 HTML、脚本、自动打开链接和任意代码。模型与图表后置于基础文字闭环；模型限受控 HTTPS 资产、大小与格式，禁止服务端任意 URL 抓取。渲染回执在实际更新可见后发送。
