# 显示页

当前可运行的显示端是 [apps/web-display](../apps/web-display/index.html)。它使用 three.js，可在桌面浏览器调试，也可通过 USB 在 Quest Browser 打开同一页面。2026-11-01 已在 Quest 3 投屏中看到新版页面与可用的 VR 入口；沉浸式会话、手柄选择和头显上的 MCP 显示回执仍待实测。

预设场景是 `grid`、`orbit`、`crystal` 和 `pedestal`。`show_scene` 也可以给出允许列表内、以 `.gltf` 或 `.glb` 结尾的 https 地址，以及位置、旋转、缩放和锚点。`render_panel` 在场景中放一块纯文本面板。`clear` 必须显式给出 `scene`、`panel` 或 `all`。

## USB 调试

本机中继启动后，通过 USB 连接并授权 Quest 的开发调试。只有一台设备时运行：

```sh
adb reverse tcp:8787 tcp:8787
adb reverse --list
```

MQDH 的 Device manager → Device actions → Browser 输入 `http://localhost:8787/` 并运行。连接多台设备时，为 adb 命令增加 `-s <PLACEHOLDER>`。USB 重连后核对转发规则。页面、配对和 WebSocket 仍走本地显示端口，不通过公网 MCP 入口。

在页面输入现有 `DEVICE_PAIRING_TOKEN`，点击连接。MQDH 投屏中可用 View 2D apps 选择对应的 Browser 窗口查看页面。投屏显示和键鼠转发是两项能力；看到页面并不能证明键盘、鼠标或沉浸控制器已经可用。

## 设备切换与恢复

当前中继只激活一个显示端。新设备通过 WebSocket 配对校验后接管显示；未鉴权连接不会挤掉当前设备。旧页面显示「已切换到另一设备」，停止自动重连。点击「切回此设备」才重新接管，短期会话过期后需要重新配对。

普通断线按 1、2、4、8、16、30 秒退避重连，并带 ±20% 抖动。重连提交本页已渲染的连续序号；手动断开会取消待执行的重连。25 秒发送心跳，60 秒没有入站消息则断开。标签页回到前台时加速已有的重连尝试。

刷新页面会丢失三维场景，因此从零请求补发，不复用存储中的旧序号。快照可将序号重置到更低的值。中继重启后需要重新配对，再恢复当前状态。

命令按顺序加载和渲染，提交一帧后才发 ACK；glTF 下载或解析失败时暂停显示连接，保留未确认状态。修复模型资源后点击「重试显示」。慢下载或后台暂停期间，MCP 可能先返回 `queued`，不能解释成已显示。

## 沉浸模式与选择

页面预先检测 VR 和透视 AR 的支持情况，默认选用可用的 VR；每次点击只申请选中的模式。会话需要 `local-floor`，可选启用手部输入。透视 AR 使用透明背景。进入后暂停桌面轨道控制，退出后恢复桌面视角；沉浸中可用头显系统菜单退出。

桌面鼠标和 WebXR 控制器的 `select` 共用场景射线选择逻辑。面板上报 `panel_id`，预设上报预设名，自定义模型上报 `model`。两路控制器提供指向线；设备是否将手势映射为 `select` 需实测。事件只留在中继，见[交互说明](03-interaction.md)。

当前锚点是固定坐标偏移，不是持久空间锚点；`head` 也尚未实现随头部移动。空间摆放、手势和长时间后台恢复仍需头显验证。

原生空间应用仍是以后的候选，不在本次本地闭环里实现。本目录不内嵌模型网页，也不保存云端长期密钥。
