# 决策

## 已确认（2026-11-01）

- 产品为原生 Quest MR 空间助手，多面板自由摆放；透视模式与现实视觉理解在同一体验中设计和验收，不另做独立相机产品。
- MCP 的主位置为 Quest 本机。自研 App 管理工具、状态、布局、视觉联动、连接就绪及 Grok Bot 启动协调。
- 复用已安装 Grok Bot App 的语音、对话和账号，不自接 Grok 模型 API，不增加自建语音层。已安装 App 的身份、版本及 Quest 语音工具能力仍待核查。
- 工具路径为 Grok Bot App → 既有托管 Bot / 连接器 → Cloudflare HTTPS 边缘 → Quest 发起的 Tunnel → 本机 MCP。Cloudflare 负责连接与转发，本机服务仍负责授权和工具业务。
- 两款 App 指日常交互，不限定操作系统进程或安装包数量。隧道优先内置自研 APK；若内置不可行但独立组件在 Quest 实测可行，可在部署阶段安装并配置自动启动的后台隧道辅助组件，日常不要求用户手动打开。载体未选定，不默认安装 Termux / Boot。
- 常在线自建 MCP 仅在明确后台 / 跨设备需求或本机实测限制下再讨论，不是默认主线。不存在旧 VPS 部署前置条件。
- 当前授权范围为仓库整理和隔离固定健康响应的 Quest Tunnel POC。仓库整理已先推送，随后隔离实测定位到 Go DNS 失败，外部回环未完成；完整原生实现、辅助组件安装、自启和永久入口不在本轮实施范围。
- 当前分支清理旧路线 / 部署材料，保留运行代码、必要协议 / 配置及验证证据；不新增备份。既有 `dca4f9e` 归档与 Git 历史保持不动。

## 工程待验证

| 项目 | 起点 | 决定所需证据 |
|---|---|---|
| Quest Tunnel 连通 | 实际 ARM64 设备、隔离固定健康端点 | 执行、出站连接和外部 HTTPS 响应逐项记录；执行与本地响应通过，Linux 发布资产在 Go DNS 阶段失败，外部请求未执行 |
| 隧道交付 | 同 APK 受控原生组件或库；条件式后台辅助组件 | Android ABI / 执行身份 / 代码装载、许可证、启动 / 停止 / 恢复、更新及凭据管理；各候选单独验证 |
| 原生技术栈 | 优先评估 Meta Spatial SDK + Compose | 多面板、透视视觉、输入及双 App 生命周期；不是已选定 SDK |
| 双 App 联动 | 自研 App 检查就绪后按系统机制打开 Grok Bot | 实际启动入口、语音工具调用、MR 可见性、输入 / 音频焦点、新帧与返回工作区 |
| 稳定入口与授权 | 本机校验调用凭据 | 稳定地址、授权导入 / 撤销 / 轮换、连接器兼容；临时健康探针不能代替 |
| 空间与任务恢复 | 内容、布局、真实空间锚点分开 | 长时任务、进程退出、摘戴休眠及跨会话恢复 |

## 已实现的协议基线

现有 Node / 桌面验证代码提供两个 localhost 端口、静态 Bearer 与独立配对凭据、三个显示工具及渲染 ACK，接受 2026-07-28 与 2025-11-25 两种协议流程。它没有 OAuth、原生 MR 或视觉输入实现，`interaction` 仅留在中继内存。具体约束见[协议基线](protocol-baseline.md)。

托管端曾通过静态 Bearer 完成实际工具调用和桌面画面对齐，见[历史验证](validation-baseline.md)。这项兼容性已有证据；Quest 上的实际语音会话和原生显示仍待验证，不能混为同一结果。

## 历史保留

既有 Mac mini、Tailscale、Cloudflare Worker、frp 路线保持否决状态。Cloudflare Tunnel 与 Worker 承载工具逻辑不同；现有 Tunnel 选择不重新启用 Worker 路线。旧 VPS / Caddy / systemd 示例和容器构建材料已从当前分支删除，未部署的示例不作为验证证据。

完整方案见[原生 MR 方案](08-native-spatial-options.md)，实施顺序见[里程碑](07-milestones.md)。
