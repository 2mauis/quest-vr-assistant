# 修复规程

1. 用 [Feature Map](FEATURE_MAP.md) 标记功能与报错操作面，复述触发条件；先 doctor 与隐私检查。
2. 自己在原操作面复现并记录 before、build_id、request_id、seq。不能复现就补条件，不猜测已修好。
3. 先提交新增独立 `test/*.test.ts` 失败用例的专用提交，再修代码。新增用例不得依赖只在 head 新增的生产模块，否则 base 的导入失败不是复现。只在设备可达的 bug 另写 `docs/repros/` 步骤与本地证据；CI 仍要求低层回归测试。
4. 最小修复；运行相关测试，构建部署，再在同一操作面取 after。头显问题必须实机确认，注入输入与无头结果分别记录。
5. PR 写 Repro (before)、Verify (after)、风险分级，隐私扫描正文和 diff；检查 CI 与独立审查。不能公开原始证据或系统整屏。
6. 用户语音结论决定是否继续；用户 明确发起合并后才进入 [v2 合并闸门](workflow-v2.md)。不自动合并。

提交与推送须服从当次授权；本次用户禁止这些操作，因此只准备可审阅改动。来源材料的“头显专属步骤替代测试”在当前 CI 中仅作补充证据，不能绕过新增失败回归用例要求。
