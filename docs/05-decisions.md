# 决策

## 已确认（2026-11-01）

- 产品为原生 Quest MR 空间助手，多面板自由摆放；透视模式与现实视觉理解在同一体验中设计和验收，不另做独立相机产品。
- MCP 的主位置为 Quest 本机。自研 App 管理工具、状态、布局、视觉联动、连接就绪及 Grok Bot 启动协调。
- 复用已安装 Grok Bot App 的语音、对话和账号，不自接 Grok 模型 API，不增加自建语音层。已安装包、版本和 Launcher 已从设备核对；当前发行包在 Quest 上被 Google Play 启动检查阻塞，尚未登录。此限制不自动授权替换产品或修改系统组件，先确认兼容发行方式。
- 工具路径为 Grok Bot App → 既有托管 Bot / 连接器 → Cloudflare HTTPS 边缘 → Quest 发起的 Tunnel → 本机 MCP。Cloudflare 负责连接与转发，本机服务仍负责授权和工具业务。
- 两款 App 指日常交互，不限定操作系统进程或安装包数量。隧道优先内置自研 APK；若内置不可行但独立组件在 Quest 实测可行，可在部署阶段安装并配置自动启动的后台隧道辅助组件，日常不要求用户手动打开。载体未选定，不默认安装 Termux / Boot。
- 常在线自建 MCP 仅在明确后台 / 跨设备需求或本机实测限制下再讨论，不是默认主线。不存在旧 VPS 部署前置条件。
- 当前授权范围包括仓库整理、隔离健康响应的 Quest Tunnel POC，以及后续明确授权的源码适配、专用具名 Tunnel / DNS、限时管理凭据和路由器 fake-IP 排除规则。用户最新明确选择继续验证 Quest App 内置 Tunnel，已完成自研限时诊断 APK 的构建与实测；结束撤下临时路由并卸载测试包。完整 MR 实现、第三方辅助组件安装和自启不在本轮范围。
- 当前分支清理旧路线 / 部署材料，保留运行代码、必要协议 / 配置及验证证据；不新增备份。既有 `dca4f9e` 归档与 Git 历史保持不动。

## 已实现的协议基线

现有 Node / 桌面验证代码提供两个 localhost 端口、静态 Bearer 与独立配对凭据、三个显示工具及渲染 ACK，接受 2026-07-28 与 2025-11-25 两种协议流程。它没有 OAuth、原生 MR 或视觉输入实现，`interaction` 仅留在中继内存。具体约束见[协议基线](04-protocol-baseline.md)。

托管端曾通过静态 Bearer 完成实际工具调用和桌面画面对齐，见[历史验证](03-validation-baseline.md)。这项兼容性已有证据；Quest 上的实际语音会话和原生显示仍待验证，不能混为同一结果。

## 历史保留

既有 Mac mini、Tailscale、Cloudflare Worker、frp 路线保持否决状态。Cloudflare Tunnel 与 Worker 承载工具逻辑不同；现有 Tunnel 选择不重新启用 Worker 路线。旧 VPS / Caddy / systemd 示例和容器构建材料已从当前分支删除，未部署的示例不作为验证证据。
