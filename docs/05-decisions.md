# 决策

## 已确认（2026-11-01）

- 产品为原生 Quest MR 空间助手，多面板自由摆放；透视模式与现实视觉理解在同一体验中设计和验收，不另做独立相机产品。
- MCP 的主位置为 Quest 本机。自研 App 管理工具、状态、布局、视觉联动、连接就绪及 Grok Bot 启动协调。
- 复用官方 Grok 网页的语音、对话和账号，不自接模型 API，不增加自建语音层。默认入口是浏览器 Custom Tabs，复用既有登录 / 网站权限，与自研连接页位于同一任务栈；WebView 仅作独立登录备用页。当前网页版本已获用户实机验收。
- 工具路径为 Grok 网页 → 既有托管 Bot / 连接器 → Cloudflare HTTPS 边缘 → Quest 发起的 Tunnel → 本机 MCP。Cloudflare 负责连接与转发，本机服务仍负责授权和工具业务；正式 Quest 工具链尚未接入。
- 日常使用从自研 App 的网页入口进入，浏览器承载页面，不限定操作系统进程数量。隧道优先内置自研 APK；若内置不可行但独立组件在 Quest 实测可行，可在部署阶段评估自动启动的后台辅助组件。载体未选定，不默认安装 Termux / Boot。
- 常在线自建 MCP 仅在明确后台 / 跨设备需求或本机实测限制下再讨论，不是默认主线。不存在旧 VPS 部署前置条件。
- 已授权工作包括仓库整理、隔离 Tunnel POC、源码适配、专用具名 Tunnel / DNS、限时管理凭据和路由器 fake-IP 排除规则，以及后续同 APK 网页封装与共享登录。Tunnel 诊断结束时撤下临时路由并卸载测试包，当前网页版本已重新安装并保留。此次提交记录网页验收；完整 MR 实现、第三方辅助组件安装和自启不在本轮范围。
- 当前分支清理旧路线 / 部署材料，保留运行代码、必要协议 / 配置及验证证据；不新增备份。既有 `dca4f9e` 归档与 Git 历史保持不动。

## 后续明确更新：同一 APK 的网页页

用户停止第三方 APK 改包与 Root 路线后，官方网页在 Quest 浏览器内已能使用既有会话收发 Bot 消息。随后用户明确要求将网页放进 Quest MCP App，作为单独页面；这替代前期“两款日常交互 App”的入口安排。保持 Quest 本机 MCP / Tunnel 主线，复用官方网页的账号、语音和连接器，不自建模型或语音后端。

现有 Android 容器已增加同包 WebView 页面及麦克风透传；正式 MCP 工具仍待接入。内嵌页不继承浏览器登录，首次登录与实际 Bot 通话单独验收，不以本机音频回环代替。原版第三方 APK 保持原样，不将其启动限制作为继续修改包或系统的理由。

用户随后要求复用浏览器 Cookie / 登录，避免重复认证。默认网页入口已改为浏览器 Custom Tabs；Quest 实测与连接页位于同一个任务栈，直接使用既有会话，App 不接触 Cookie 内容。WebView 保留为独立登录的备用页。用户提供的 Rakazo 源码是独立客户端 / 服务端产品，可参考 Android 构建和生命周期，但它使用自己的账号、会话和模型 / 语音服务，不将其编译结果视为官方 Grok 客户端，也不因此迁移现有主线。

当前 `0.3-browser` 的网页登录 / 语音体验已由用户实机确认通过。该确认作为用户验收记录，与自动化页面 / 麦克风证据分别保留；不扩展为尚未实现的正式 Quest MCP、MR、视觉新帧或休眠保活已通过。

## 已实现的协议基线

现有 Node / 桌面验证代码提供两个 localhost 端口、静态 Bearer 与独立配对凭据、三个显示工具及渲染 ACK，接受 2026-07-28 与 2025-11-25 两种协议流程。它没有 OAuth、原生 MR 或视觉输入实现，`interaction` 仅留在中继内存。具体约束见[协议基线](04-protocol-baseline.md)。

托管端曾通过静态 Bearer 完成实际工具调用和桌面画面对齐，见[历史验证](03-validation-baseline.md)。当前 Quest 网页基础语音另有用户验收；语音触发正式 Quest MCP 与原生显示仍待实现和联合验证。

## 历史保留

既有 Mac mini、Tailscale、Cloudflare Worker、frp 路线保持否决状态。Cloudflare Tunnel 与 Worker 承载工具逻辑不同；现有 Tunnel 选择不重新启用 Worker 路线。旧 VPS / Caddy / systemd 示例和容器构建材料已从当前分支删除，未部署的示例不作为验证证据。

完整方案见[原生 MR 方案](01-native-spatial-plan.md)，实施顺序见[里程碑](02-milestones.md)。

## 评审后仍待拍板

[原生空间评审](06-native-spatial-review.md) 已覆盖到网页语音验收。上面的已确认项保持有效：官方网页走 Custom Tabs，改包 / Root 已停止，本机 MCP 仍是本分支记录的主线。下列事项仍要机主选择：

- 在把 MCP 进程迁入 APK 之前，是否先用现有中继让网页语音触发三次显示工具，并在头显上取得 `delivered: true`。
- 原生运行时是否定为 Spatial SDK + Compose。Custom Tab 由浏览器承载，不能当作该场景里的面板。
- 面板是否必须在网页前台时仍作为系统窗口可见。
- 公网入口继续用每次更换主机名的 Quick Tunnel，还是进入正式 VPS / 另行授权的稳定主机名。诊断用的具名健康隧道未接入中继。
- 进程重启后是否必须补发旧命令。当前中继从 1 重新计数。
- 首包从工具调用发出起算，还是从语音结束起算。网页语音验收没有延迟样本。
