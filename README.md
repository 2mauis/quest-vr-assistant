# Quest 原生 MR 空间助手

> 当前检查点：双轨显示重构，2026-11-01。桌面浏览器可以驱动新的网页显示；头显安装与语音闭环仍待机主实机验收。结构见 [双轨架构](docs/07-architecture-two-track.md)。历史实机证据见 [实机记录](docs/03-validation-baseline.md#原生工作区联调与宽屏共存)。

显示分成两条轨道。**网页显示**用 React Three Fiber、`@react-three/xr`、`@react-three/uikit` 和 `@react-three/drei` 呈现预设、面板、glTF 和 WebXR。**原生壳**用 Spatial SDK 把 Grok 官方网页（Custom Tabs）和这块网页显示（WebView 面板）放在一起。中继、三个工具的名称和输入 schema、`seq` / ACK / `delivered` 保持不变。不另接模型 API，不重做语音。

Quick Tunnel 继续作为这条重构的公网连接。本分支不修改 DNS、WAF、账号或具名 Tunnel。具名 Tunnel 的下一步需要机主批准。

**当前阶段 1 路径：**工具客户端 → 固定具名 Tunnel 的 HTTPS `/mcp` → 开发宿主上的 Node 中继 → Quest 原生显示客户端。三个工具已从调试客户端打通；Grok 网页语音触发同一路径仍待验收。

目标路径是 Grok Bot 网页 → 既有托管 Bot / 连接器 → Cloudflare HTTPS 边缘 → Quest 主动建立的 Tunnel → Quest 本机 MCP。MCP 迁入 APK 和正式 Tunnel 随 App 管理尚未完成。

用户后续明确将网页放进 MCP App。当前默认通过浏览器 Custom Tabs 在同一 App 任务栈打开独立页面，复用浏览器已有登录；APK 内另保留独立登录的 WebView 备用页。隧道优先内置；若内置不可行但独立组件在 Quest 实测可行，可另行评估后台辅助组件，尚未选定其他载体。

## 已完成与已验证

- **原生显示主体：**Spatial SDK + Compose 工作区、透视背景、四种内置模型、纯文本多面板、同 ID 更新和清除已实现。具名 `/mcp` 的 `show_scene`、`render_panel`、`clear` 均取得原生 `rendered` / `delivered: true`，调用源为调试客户端。
- **真实画面与布局：**MQDH `metacam` 已拍到已登录 Bot 宽屏页、可读原生面板和模型同时出现。修复面板背面朝向和预设 GLB 索引导致的原生崩溃；默认紧凑右侧布局，提供逐块缩放和“收回右侧”。普通 ADB 截图与软件 ACK 不替代 VR 实拍。
- **网页入口与登录保留：**原签名覆盖更新保留浏览器登录，直达已确认的 Bot。独立横屏任务默认 `1280×720 dp`；连续打开三次复用同一任务，未新增 Custom Tab。真实地址仅由私有构建配置输入。旧 `0.3-browser` 的登录 / 基础网页语音已获用户验收，不等于新工作区的语音工具联动通过。
- **交互实现与部分验证：**面板抓取边缘、缩放按钮、模型碰撞体及抓取组件已实现。设备上的 XR 合成输入验证了面板拖动、模型手势抓取和缩放；去掉模拟输入层后已捕获实体右手柄的面板 `Hover` / `Select` 与缩放记录。**实体手柄直接抓取模型仍未通过。**
- **配对与恢复：**短期会话和独立恢复授权经 Android Keystore 加密保存。原签名更新、App 重开、短期会话过期续期，以及 USB 显示通道断开 / 恢复已验证无需重新配对；主动移除连接、授权失效和设备接管保留停止边界。
- **Tunnel 与构建：**固定具名 Tunnel 已接现有中继，`qvr` 使用该入口。早期 APK 内置 Tunnel 探针已通过 App UID、四条连接、外部健康回环及限时生命周期验证，但尚未成为正式常驻服务。GitHub Actions 已有原生 APK 与中继检查流程；本次提交尚不代表新的远端构建通过。
- **本轮检查：**原生核心 12 项、中继 22 项、桌面浏览器 6 项通过；原生 APK 编译、签名、16 KiB 对齐、预设和网页入口检查通过。当前实机诊断包不携带 XR Operator 输入层。

构建、同签名更新、CI 临时签名限制和功能边界见 [原生工程 README](apps/quest-app/spatial/README.md)。

## 待测试与已知问题

1. **优先处理实体模型输入：**实体手柄已能命中文字面板，模型直接抓取仍无成功证据。按“输入识别 → 焦点 → 射线命中 → 抓取状态 → 真实位移”逐段排查；不以注入输入代替实体手柄验收。
2. **窗口共存与位置恢复：**已拍到并排画面，但切回原生工作区时出现网页隐藏，后续打开时也出现网页偏出视野。持续共存、输入 / 音频焦点切换、返回后自动纠偏仍需修复验证。现有进入时定位与“收回右侧”不等于已实现自动越界恢复。
3. **单网页生命周期：**重复打开未新增页面；历史任务栈仍见隐藏旧页。重启、同签名更新、网页关闭后重开，以及旧页收敛仍需完整回归，保留当前对话与登录，不关闭无关浏览器窗口。
4. **真实 Grok 语音闭环：**从头显网页语音实际触发三个工具，对齐请求、回执与 VR 画面；验证通话期间焦点和麦克风释放。固定入口连接器交接完成后再撤下旧 Quick 通道。
5. **扩展与恢复场景：**多面板、双手 / 角落缩放、外部模型成功与失败、设备接管、摘戴 / 休眠、真实 Wi-Fi 切换和长时运行。USB 转发恢复不能代替这些验收。
6. **性能与独立运行：**脱离开发机的端到端运行尚未通过；至少取得 100 个有效样本后再统计首包 P50 / P90。

## 后续尚未实现

Quest 本机 MCP 正式服务、正式 Tunnel 生命周期 / 自启、相机新帧工具、真实空间锚点和跨进程持久化仍属于后续开发。现有场景可从仍运行的中继重新取得，不代表中继重启后会恢复已丢失的内存状态。原版第三方 APK 改包 / Root 路线已停止。

下次从上面的实体模型输入、窗口共存和位置恢复继续。调试以新鲜设备状态、MCP 回执和 VR 实拍闭环，避免反复要求人工确认；截图、房间、会话、秘密及原始日志仅留本机，不进入仓库。
